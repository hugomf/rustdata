### 4 · `Makefile` — Single Source of Truth for Releases
Entry points for every release action; callable by humans and the Gitea Actions workflow.

```makefile
VERSION_FILE   = cargo.txt   # stores current_version string
CHANGELOG_FILE = CHANGELOG.md

.PHONY: bump-version check publish-dry-run publish tag changelog

check:
    cargo fmt && cargo clippy --all-targets --all-features && cargo test --workspace

bump-version:
    @# Usage: make bump-version BUMP=major|minor|patch [DRY=1]
    @# Reads current_version from $(VERSION_FILE), increments, writes back

publish-dry-run:
    @cargo publish -p rustdata-macros --dry-run
    @cargo publish -p rustdata-migrations --dry-run
    @cargo publish -p rustdata-core     --dry-run

changelog:
    @# format $(VERSION_FILE) version + git log since last tag into $(CHANGELOG_FILE)

tag:
    @# reads $(VERSION_FILE); creates and pushes signed tag vX.Y.Z to all remotes

publish: check bump-version publish-dry-run tag
    @cargo publish -p rustdata-macros
    @cargo publish -p rustdata-migrations
    @cargo publish -p rustdata-core
```

### 5 · `scripts/release.sh` — Handles `$@` for the Gitea Actions workflow
```bash
# Usage:
#   ./scripts/release.sh                         → interactive (prompts for bump type)
#   ./scripts/release.sh --bump minor --yes     → fully non-interactive
#   ./scripts/release.sh --dry-run               → validate only, no publish
# Steps:
#   1. `make check`                              → fmt + clippy + test
#   2. `make publish-dry-run`                    → cargo publish --dry-run all crates
#   3. `make bump-version`                       → semver bump in Cargo.toml files
#   4. `make changelog`                          → append new CHANGELOG.md section
#   5. `make tag`                                → git commit + signed tag vX.Y.Z
#   6. `make publish`                            → cargo publish each crate sequentially
```

### 6 · `CHANGELOG.md` (auto-generated template)
Required by the crates.io publishing guide. The `make changelog` target appends a section for each new version.

### 7 · `cargo.txt` — Single Source of Truth for the current version
`cargo publish` reads version from `Cargo.toml` directly. After integration with a version management tool (e.g., `cargo-release`), a `cargo.txt` file similar to `setup.py` `__version__` can be lost. The recommended approach is to programmatically read from `cargo metadata` or keep it in `Cargo.toml` exclusively. For our Makefile integration we keep a `cargo.txt` file for convenience (`make bump-version` reads/writes it then updates `Cargo.toml` files; alternatively replace with `cargo-release`).

### 8 · Add GitHub Remote
GitHub can be added as a named remote:
- Run: `git remote add github https://github.com/hugomf/rustdata.git`
- Push: `git push github --all` and `git push github --tags`
- Purpose: this gives the new Gitea Actions workflow a mirror target, enables tools like `cargo-release` that assume a GitHub-style origin, and lets issues happen on the canonical GitHub if desired. **User confirms GitHub org/user.**

### 9 · `.gitea/workflows/release.yml` — Gitea CI/CD
Gitea now ships `actions/checkout@v4` as an official action (Gitea 1.19+ mirrors the GitHub Marketplace). This replaces the GitHub Actions file entirely.

Two jobs:
- **`validate`** — runs on every push and PR: `cargo fmt`, `cargo clippy`, `cargo test --workspace`, `cargo publish --dry-run`
- **`release`** — `workflow_dispatch` input `bump` (`major`/`minor`/`patch`); runs `scripts/release.sh`; requires `CARGO_REGISTRY_TOKEN` secret configured in Gitea repo settings
